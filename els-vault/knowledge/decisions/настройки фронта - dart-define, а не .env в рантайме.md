# Настройки фронта - dart-define, а не .env в рантайме

## Решение

Настройки Flutter-приложения задаются **при сборке** через `--dart-define`
и читаются константами `String.fromEnvironment` в `lib/helper/app_config.dart`
и `api_config.dart`. Для удобства локальной работы значения лежат в
`frontend/env/local.json` (в `.gitignore`, шаблон — `env/example.json`) и
передаются флагом `--dart-define-from-file`. В docker те же значения идут
build args через `infra/docker-compose.yml`.

## Почему не `.env`

- **Рантайма для него нет.** Flutter компилируется в нативный код и в JS.
  На телефоне переменных окружения не существует, браузер их не отдаёт.
  `.env` бэкенда работает потому, что там живой процесс Python, читающий файл
  при старте; у приложения такой возможности нет.
- **`flutter_dotenv` кладёт файл в ассеты приложения** — то есть в APK и в
  бандл веб-сборки. Любой, кто распакует APK или откроет вкладку Network,
  прочитает его целиком. Секретность нулевая, зато добавляется рантайм-ошибка
  «файл не найден».
- `--dart-define` подставляется на компиляции, поэтому неиспользуемые ветки
  вырезаются tree shaking'ом. Это уже сработало: после переноса адреса API
  в `ApiConfig` старый адрес `185.154.193.42` **исчез из собранного JS
  полностью**, потому что `kIsWeb` — компайл-тайм константа.

## Правило про секреты

**В клиентском приложении секретов не бывает.** Всё, что попало в сборку —
публично. Ключи внешних сервисов, пароли и токены живут только на бэкенде,
а приложение получает нужное через наш API. Если однажды понадобится платный
геокодер или карты по ключу — ключ идёт в `.env` бэкенда, а бэкенд проксирует
запрос, а не отдаёт ключ клиенту.

## Что вынесено, а что осознанно нет

Вынесено: `API_ORIGIN`, `MAP_TILE_URL`, `OSM_USER_AGENT` — то, что реально
меняется между окружениями или требует настройки под продукт.

Не вынесено намеренно: координаты центра карты по умолчанию (Краснодар),
ссылка на сайт заказчика, названия экранов. Это **продуктовые константы**, а не
настройки окружения: они одинаковы во всех средах, и вынос их в переменные
только добавил бы способов собрать приложение неправильно.
