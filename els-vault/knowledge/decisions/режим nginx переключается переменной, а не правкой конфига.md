# Режим nginx переключается переменной, а не правкой конфига

## Решение

Конфиг nginx разложен в каталог `infra/nginx/`:

```
app.conf     статика, API, Swagger, оболочка Flutter — общее
acme.conf    проверка владения доменом для Let's Encrypt
http.conf    server :80, обслуживает всё
https.conf   server :80 (только ACME + редирект) + server :443
```

Какой режим включён, решает `NGINX_CONF` в `.env`: `http.conf` или
`https.conf`. Применяется через `make prod-nginx`.

Сертификат выпускается по webroot отдельным контейнером `certbot` в профиле
`tools` — в обычный `up` он не попадает. Продление стоит в cron на 4:17
ежедневно и вызывает `make cert-renew`, который ещё и перезагружает nginx.

## Почему

- HTTP и HTTPS отличаются только обвязкой, а сорок строк с API, статикой и
  кэшем у них общие. Две копии однажды разъедутся — в этом коде уже
  находились девять одинаковых опечаток и тринадцать одинаковых геттеров.
- Откат должен занимать минуту. Вернуть `http.conf` и повторить команду —
  это доступно человеку в три часа ночи, в отличие от «поправить конфиг».
- Общая часть монтируется **каталогом**, а не файлом, поэтому правки в ней
  применяются обычным reload — ловушка с inode на них не действует, см.
  [[правка примонтированного файла не доезжает до контейнера]].
- Плагин certbot для nginx рассматривали и отклонили: он правит конфиг
  сам, а конфиг у нас в git и монтируется только на чтение.
- Caddy с автоматическим TLS рассматривали и отклонили: пришлось бы
  переписывать уже отлаженную раздачу статики, кэш-заголовки и проксирование.

## Цена решения

Два файла вместо одного, и при изменении общей части надо помнить, что она
общая. Плюс переключение режима требует пересоздания контейнера, а не
перезапуска, — потому что файл режима монтируется поштучно.

Отдельно: **HSTS не включён**. Заголовок велит браузеру не ходить на домен
по HTTP вообще и запоминает это на месяцы; с ним откат на `http.conf`
перестал бы работать. Строка лежит в `https.conf` закомментированной.

## Когда вернёмся

HSTS включаем, когда сертификат и автопродление отработают хотя бы один
цикл — то есть после 9 ноября 2026, если в логе `/var/log/certbot-renew.log`
не будет сюрпризов.
