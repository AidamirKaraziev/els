# Список дефектных актов за период отчёт берёт с сервера, а не из строк матрицы

## Решение

На экране «Отчёты» плитка «Дефектных актов N» показывает `counts.defects`
из сводки, а тап «открыть список» запрашивает `GET /reports/works/defects`
с теми же фильтрами и тем же `object_ids`. В PDF акты выходят обособленным
разделом «Дефектные акты за период» (`_defects_section` в `reports_pdf.py`),
собранным тем же запросом. Число в плитке, длина списка и «Всего» в PDF
обязаны совпадать — это проверяется на стенде: 6 / 6 / 2 при выборе двух
лифтов.

## Почему

- Матрица показывает страницу в 25 объектов, а сводка считает весь отбор.
  Собирать список из строк на экране значило бы показывать меньше, чем в
  плитке, как только объектов больше страницы.
- Считать акты по дате создания, а не по месяцу плана: акт — событие, у него
  есть дата; план ТО режется по месяцу отдельно, см.
  [[период отчёта режется по датам, а ТО — по плановому месяцу целиком]].
- Отдельная ручка вместо вложения списка в `/reports/works`: список нужен
  только по тапу, а сводка грузится при каждой смене фильтра.

## Цена решения

Три места знают об одном отборе — сводка, список, PDF. Держит их вместе
`_object_conditions`: условия отбора описаны один раз, и любая новая
ручка обязана идти через него.

## Когда вернёмся

Если заказчик попросит акты в Excel-выгрузке — раздел появится и там, тем же
запросом. Если список за период станет длиннее сотни — нужна постраничность
у `/reports/works/defects`, сейчас её нет.
