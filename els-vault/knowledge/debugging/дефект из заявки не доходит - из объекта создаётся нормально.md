# Дефект из заявки не доходит, из объекта создаётся нормально

Найдено на живом телефоне 7 сентября 2026, на первой раздаче APK механикам
(версия 1.0.1). Заявка **889**: дефект создан со снимками, механик ошибки не
увидел — и дефект не нашёлся ни у механика, ни у прораба, ни у админа.
Сообщения «нет интернета» тоже не было.

## Что воспроизводится

| Откуда создаём дефект | Результат |
| --- | --- |
| из объекта | доходит, виден |
| из заявки ТО | **не доходит** |
| из заявки, где механик наблюдатель | **не доходит** |
| из работы по ТО, из пункта чек-листа | не проверено |

Остальные варианты привязки надо пройти так же: `DefectLink` знает четыре —
акт ТО, пункт чек-листа, заявка, объект
(`frontend/lib/mechanic/data/defect_link.dart`).

## Две версии, между которыми не выбрано

Замер, который их разводит, — на сервере:

```
docker exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select id, object_id, order_id, title, created_at from defective_acts order by id desc limit 5;"'
```

1. **Запрос не дошёл.** Дефект не уходит напрямую: он кладётся в очередь
   отложенных действий и отправляется фоном
   (`frontend/lib/mechanic/data/mechanic_workspace.dart:445`,
   `frontend/lib/mechanic/data/outbox.dart`). Это объясняет молчание про
   интернет — кнопку нажали, очередь приняла. Если сервер ответил 422 (скажем,
   на привязке `order_id`), действие должно уйти в «отклонённые» и показаться
   человеку — проверить, что этот показ вообще есть на экране.
2. **Дошёл, но показать некому.** Списки дефектов у прораба строятся по
   объекту и по акту ТО (`frontend/lib/foreman/defects/defects_repository.dart:42`),
   заявки среди них нет. Тогда строка в базе есть, а экрана для неё нет —
   и это смыкается с пожеланием видеть все дефекты сразу, см.
   [[пожелания к окну задач - единая лента и одинаковые окна ролей]].
