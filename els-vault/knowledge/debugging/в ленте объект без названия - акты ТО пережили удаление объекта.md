# В ленте «Объект без названия» — акты ТО пережили удаление объекта

После выката E11 в ленте «Работы» на проде стояли строки №272–287:
«Объект без названия · Принята · 337 д». Похоже на регрессию ленты или
формы — но в таблице `order` таких id нет вовсе.

Это вторая половина ленты — `acts_fact`. У 16 актов ТО `object_id IS NULL`:
объект когда-то удалили, а FK объявлен `ondelete="SET NULL"`
(`models/act_fact.py`), и акты остались висеть без объекта, год как
«Принята». Лента оба потока джойнит через `outerjoin`, строка выживает, а
фронт на `object == null` пишет заглушку (`work_item.dart`). Старая
диспетчерская лента такие строки просто не показывала.

## Как починили

Пока никак — решение за пользователем: удалить 16 актов руками на проде
(перед этим `pg_dump -t acts_fact -t acts_fact_step_photos`; ссылки из
`planned_to` снимутся SET NULL, фото — CASCADE) или добавить фильтр
`object_id IS NOT NULL` в `_maintenance_branch` (`crud_work_feed.py`).

## Урок

«Объект без названия» в ленте — сначала `SELECT … FROM acts_fact WHERE
object_id IS NULL`, а не поиск по `order`: номер строки ленты — это id
в своей таблице, у заявок и актов они независимы. И удаление объекта не
чистит его ТО — это стоит помнить при любом «архивировании» объекта.
