# Без сети приложение открывало экран входа при живом refresh-токене

## Симптом

Аудит APK 1.0.4 против сайта (E10·S11): механик включил авиарежим, закрыл
приложение, открыл снова — экран входа. При этом выходить он не нажимал, а
после включения сети и перезапуска приложение входило само, без пароля.

Второе замечание из того же аудита: после выхода форма входа пустая, почту
приходится набирать заново.

## Настоящая причина

`AppRouter.restore()` при старте требовал два сетевых шага подряд:

1. `Api.restoreSession()` — если access старше 30 минут, обменивает refresh на
   новую пару на сервере. Без сети `_doRefresh` честно возвращал `false` и
   токены **не стирал**.
2. `loadProfile()` — `GET /auth/me`, всегда сеть. Без сети — `false`.

Роутер трактовал любой `false` как «сессии нет» → экран входа. Токены на
диске оставались, поэтому следующий старт с сетью проходил. То есть это не
разлогин, а ворота на старте, которые не отличали «нет сети» от «нет сессии».

Почту не помнили просто потому, что форма подрядчика никогда её не сохраняла.

## Исправление

- `Api.restoreSession()` после попытки обновления возвращает
  `TokenStore.hasSession`: отказ по сети оставляет пару на диске → `true`,
  отказ сервера стирает её через `_dropSession` → `false`.
- `loadProfile(offlineFromCache: true)` — только из `restore()`: ответ
  `/auth/me` кладётся в `SharedPreferences` (`profile_cache`) при каждом
  удачном входе, а без сети читается оттуда. На экране входа кеш не читают:
  он мог остаться от прежнего вошедшего. `resetSession()` его стирает.
- Форма входа сохраняет почту (`last_login_email`) после удачного входа и
  подставляет при открытии. Пароль не храним: телефон механика может быть
  общим или потерянным.

Версия 1.0.5+6.

## Как проверить

Войти → авиарежим → закрыть и открыть приложение → лента работ из локальной
базы, шапка «офлайн» → включить сеть → первый запрос обновит пару. Выйти →
в поле почты стоит прежний адрес, пароль пустой.
