# flutter pub get в контейнере переписывает pubspec.lock и ломает анализ

## Симптом

Прогон `flutter analyze` в контейнере на новом экране отчётов выдал десяток
ошибок вида «The method 'read' isn't defined for the type 'BuildContext'».
Выглядело как мои ошибки в коде.

Проверка соседнего, давно работающего виджета «Просроченные ТО» дала **те же
ошибки** — а он собирается в CI и живёт в репозитории неделю.

## Настоящая причина

Команда запускалась так:

```bash
docker run --rm -v "$PWD/frontend":/app -w /app \
  ghcr.io/cirruslabs/flutter:stable \
  bash -c "flutter pub get && flutter analyze lib/screns/report"
```

Каталог примонтирован на запись, значит `flutter pub get` пишет в **настоящий
`pubspec.lock` репозитория**. Версии в `pubspec.yaml` заданы широко
(`url_launcher: any` и подобное), резолвер подтянул другие, и `flutter_bloc`
перестал реэкспортировать `provider` — отсюда пропавший `context.read`.

`git status` показал 127 изменённых строк в локе, которых я не заказывал.

## Как починили

```bash
git checkout frontend/pubspec.lock
```

Проверку сделали настоящей сборкой — `make web-build`, то есть тем же путём,
которым фронт собирает CI. Она прошла: и `context.read`, и `launchUrl` в
зафиксированных версиях есть.

## Урок

**`flutter pub get` на примонтированном каталоге — это правка репозитория, а
не чтение.** Перед ним стоит понимать, что лок изменится, и после — смотреть
`git status`.

**Проверять фронт надо сборкой, а не анализатором.** `make web-build` делает
`pub get` внутри слоя образа и лока не касается. Анализатор без прогретого
кэша пакетов вообще не запускается: `dart format` в тех же условиях падает с
`PathNotFoundException` на `flutter_lints`.

Если анализатор ругается на код, который заведомо работает в проде, —
подозревать окружение, а не код. Быстрая проверка: прогнать его на старом
файле, который точно собирался.

Отдельно: обновление `pubspec.lock` в этом проекте — **осознанная отдельная
задача**, она давно висит в приоритетах. Делать её случайным побочным
эффектом проверки нельзя: широкие диапазоны версий означают, что лок и есть
единственное, что держит сборку воспроизводимой.
