# Тест не даёт открыть ручку молча

`backend/tests/test_every_route_declares_access.py` обходит маршруты
собранного приложения и падает, если у ручки не объявлен доступ.

```python
def _declares_access(route) -> bool:
    stack = list(route.dependant.dependencies)
    while stack:
        dependency = stack.pop()
        if dependency.call is deps.get_current_user:
            return True
        stack.extend(dependency.dependencies)
    return False
```

Публичные ручки перечислены в наборе `PUBLIC` парами «метод, путь». Второй
тест следит за обратным: запись в `PUBLIC` не должна пережить саму ручку.

## Почему так

Ручка без проверки доступа не падает и не ругается — она просто открыта.
Заметить это можно только глазами, а глазами 170 ручек не проверяют. Именно
так в проекте и накопились 27 открытых:
[[ручки открывались не удалением проверки, а её комментированием]].

Обход идёт по дереву зависимостей, а не по верхнему уровню, потому что
`require(Permission.X)` возвращает вложенную функцию — сама она про доступ
ничего не знает, а вот её зависимость `get_current_user` знает.

Смотреть надо именно на собранное приложение. Проверка по тексту файла
принимает закомментированную зависимость за рабочую — на этом уже
обожглись дважды.

## Что важно не забыть

Тест проверяет, что доступ **объявлен**, а не что объявлен правильно.
Второе — дело `test_role_access_on_endpoints.py`, где для показательных ручек
перечислено, какая роль получает `200`, а какая `403`.

Открыть новую публичную ручку теперь можно только дописав её в `PUBLIC`. Это
намеренно: строка в дифе видна ревьюеру, а отсутствие зависимости — нет.

В `PUBLIC` попадают и служебные маршруты FastAPI (`/docs`, `/redoc`,
`/api/v1/openapi.json`). Путь к схеме зависит от префикса API — при смене
`API_V1_STR` тест про устаревшие записи упадёт первым и подскажет.

Приём переносится на любую сквозную обязанность ручки: так же можно ловить
отсутствие пагинации или незадекларированную схему ответа.
