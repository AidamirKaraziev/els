# Тестовые учётки локального стека — какая роль под каким логином

Проверять экран роли надо под этой ролью: видимость по участкам, пункты
меню и права на действия у прораба, механика и диспетчера разные, и под
админом половина расхождений не видна.

Логины на локальном стеке (`make up`, `localhost:8080`):

| Роль             | Логин           |
|------------------|-----------------|
| Админ            | `1`             |
| Прораб           | `pr@mail.ru`    |
| Механик          | `m@mail.ru`     |
| Инженер-наладчик | `arh@mail.ru`   |
| Диспетчер        | `d@mail.ru`     |
| Клиент           | `owner@mail.ru` |

Пароль у всех шести один. **Здесь его нет и быть не должно**: `els-vault/`
лежит внутри репозитория, а пароли в git не уезжают — см. правило «Не коммить
секреты» в `CLAUDE.md`. Пароль спрашивать у владельца проекта.

## Агент паролей не вводит

Claude Code не вводит пароли в поля ни при каких условиях — разрешение
пользователя этого не меняет. Значит проверку под ролью в браузере начинает
человек: он логинится сам, а дальше агент может смотреть уже открытый экран
и водить по нему.

Практический порядок для визуальной проверки фронта:

1. Человек открывает `localhost:8080` и входит под нужной ролью.
2. Агент работает с уже открытой вкладкой — читает экран, жмёт, сверяет с
   макетом.

## Кэш сбивает проверку чаще, чем кажется

Flutter web регистрирует service worker (`flutter_service_worker.js`), и он
переживает обычную перезагрузку. После `make web-build` браузер показывает
**старую** сборку, и это выглядит как «изменения не приехали».

Проверять так: приватное окно (там service worker не зарегистрирован) или
DevTools → Application → Service Workers → Unregister. Что сервер отдаёт на
самом деле — видно без браузера:

```
curl -s http://localhost:8080/main.dart.js | grep -c 'нужная строка'
```

Кириллицу dart2js экранирует в `\uXXXX`, так что искать русскую строку в
`main.dart.js` напрямую бесполезно — grep даст ложный ноль.
