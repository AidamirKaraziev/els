# Месяц из двенадцати колонок разворачивается в строки через UNION ALL

В `planned_to` месяц — это отдельная колонка (`january_to_id` …
`december_to_id`), а не строка таблицы. Пока запрос про один месяц, хватает
карты `_PLANNED_MONTH_COLUMN`. Как только вопрос звучит «все месяцы, что уже
прошли», колонки приходится разворачивать в строки:

```python
branches = [
    select(
        PlannedTO.object_id.label("object_id"),
        PlannedTO.year.label("year"),
        literal(month_number).label("month"),
        column.label("act_id"),
    ).where(column.isnot(None), PlannedTO.year.in_(year_strings))
    for month_number, column in _PLANNED_MONTH_COLUMN.items()
]
cells = union_all(*branches).subquery("planned_cells")
```

Дальше `cells` присоединяется как обычная таблица, и месяц становится
нормальным полем, по которому можно фильтровать и сортировать.

## Почему так

- Нормализовать `planned_to` в «строка на месяц» — значит переписать чужой
  экран графика ТО на 5000 строк, который пишет в эти колонки двенадцатью
  почти одинаковыми блоками. Плюс миграция с бэкфиллом на живой таблице.
- `UNION ALL`, а не `UNION`: дубликатов между ветками быть не может, ветки
  не пересекаются по определению. Дедупликация стоила бы сортировки на
  пустом месте.
- Фильтры (`column.isnot(None)`, год) стоят **внутри каждой ветки**, до
  слияния: так до объединения доходит только заведённое.

## Что важно не забыть

- **Год в колонке строковый.** Сравнивать перечислением известных значений
  (`.in_(["2025", "2026"])`), а не `CAST`: в колонку пишут руками, и одна
  строка вроде «2025 г.» уронила бы весь запрос. Тест на это есть.
- **Сортировка по строковому году** совпадает с числовой, только пока годы
  четырёхзначные. Сейчас это так, но допущение молчаливое.
- **Двенадцать веток — двенадцать проходов по таблице.** На 47 объектах
  боевой базы неважно; при росте до тысяч это первое место, куда смотреть.
- Соединения с объектом и актом — **внутренние**. Ячейка без объекта это
  осиротевший график (`object_id` уходит в NULL при удалении объекта), и в
  статистику она попадать не должна.

Приём пригодится везде, где понадобится разрез по всем месяцам сразу:
годовой отчёт по графику, выгрузка плана ТО, сверка периодичности.
