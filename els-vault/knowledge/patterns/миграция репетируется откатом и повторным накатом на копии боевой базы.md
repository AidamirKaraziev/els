# Миграция репетируется откатом и повторным накатом на копии боевой базы

Перед выкатом миграции авторизации (`b4e2a7c19f30`) её прогнали на
восстановленной копии боевой базы в обе стороны и отдельно проверили
поведение при сбое. Заняло десять минут и заменило все рассуждения о том,
«должно сработать».

## Как

Копия боевой базы уже стоит локально и уже мигрирована. Значит откат даёт
ровно то состояние, в котором находится прод:

```
docker exec postgres pg_dump -U postgres -d postgres > before.sql
docker exec backend alembic downgrade -1
docker exec backend alembic upgrade head
```

Между шагами — снимок цифр: сколько пользователей, объектов, заявок, связей
с участками. Сходятся до и после — данные не потерялись.

Третий опыт, самый важный: подложить ровно ту порчу данных, на которой
миграция обязана остановиться, и посмотреть, что останется от базы.

```
update universal_users set email = 'PR@MAIL.RU' where id = 42;
```

## Что это дало

- откат — 0,3 секунды, схема возвращается к боевому виду;
- накат — 7 секунд на 20 пользователях; время держат проверки bcrypt по
  администраторам, от объёма таблиц оно почти не зависит;
- при сбое база **цела**: ревизия прежняя, старые имена колонок на месте,
  новых таблиц нет, все записи на месте.

Последнее — не удача, а свойство: `alembic/env.py:71` оборачивает миграцию в
одну транзакцию, а PostgreSQL умеет откатывать DDL. Промежуточного состояния
«половина переименована» не бывает, хотя миграция успевает переименовать
колонки до того, как дойдёт до проверки email.

## Что важно не забыть

**Дамп всё равно нужен.** Обратимо не всё: миграция сбрасывает пароль
администраторам со слабыми паролями из списка заглушек, и старых хешей нет
нигде. Откат их не вернёт, вернёт только дамп.

**Проверить, что таблица, собранная миграцией, никем не правится.**
`user_divisions` заполняется из `division_id` и в коде только читается —
поэтому цикл «откатил, накатил» восстанавливает её один в один. Если бы
приложение её правило, откат терял бы данные молча.

**Репетировать на свежем дампе.** Копия месячной давности не покажет
дублей email, появившихся с тех пор.
