# Конфигурация - .env через BaseSettings и свойство DB_URL

Сверено с кодом 2026-08-19. Прежняя редакция называла функцию `get_url()` и
переменную `DB_PASSWORD` — ни того, ни другого в коде нет и, судя по всему,
не было уже давно.

## Как устроено

Настройки — класс `Settings(BaseSettings)` в `src/config.py`, значения
приходят из окружения и из `.env`. Строка подключения собирается не
функцией, а **свойством**:

```python
@property
def DB_URL(self):
    return f"postgresql://{self.DB_USER}:{self.DB_PASS}@..."
```

Переменные базы: `DB_USER`, **`DB_PASS`**, `DB_HOST`, `DB_PORT`, `DB_NAME`.
Именно `DB_PASS`, не `DB_PASSWORD` — в compose есть подстановка
`DB_PASS: ${DB_PASS:-${DB_PASSWORD}}`, которая терпит оба имени, и отсюда
путаница.

Потребитель ровно один — `src/session.py:6`, `create_engine(settings.DB_URL)`.

## Обязательное

Без `SECRET_KEY`, `FIRST_SUPERUSER` и `FIRST_SUPERUSER_PASSWORD` приложение
не стартует, и это намеренно: у `SECRET_KEY` был случайный дефолт, из-за
которого токены протухали на каждом рестарте, а суперадмин с дефолтным
паролем — открытая система. Те же переменные обязаны быть в CI, иначе
`create_initial_data()` в conftest падает и тесты не идут вовсе.

`.env` **не коммитить**. В docker переменные пробрасываются в сервисы
`backend` и `postgres`; топологию задаёт compose, а не `.env` — см.
[[бэкенд в контейнере падал на DB_HOST из локального .env]].
