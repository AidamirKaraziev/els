# Шпаргалка команд

Что набирать, когда забыл. Всё, кроме раздела «На сервере», запускается
**из корня репозитория**. Полный список целей — `make help`.

## Прод-база в pgAdmin

Постгрес на проде наружу не смотрит: порт привязан к `127.0.0.1`. Клиент
подключается через SSH-туннель. Хост `els-db` уже описан в `~/.ssh/config`.

```bash
ssh -f -N els-db
```

| Поле в pgAdmin | Значение |
|---|---|
| Host | `127.0.0.1` |
| Port | `5434` |
| Database | `postgres` |
| Username | `els_admin` |

Пароль лежит в `.env` на сервере:

```bash
ssh els 'grep -E "^DB_(PASSWORD|PASS)=" /var/www/els/.env'
```

Погасить туннель:

```bash
pkill -f "ssh -f -N els-db"
```

Проверить, жив ли он:

```bash
pgrep -fl "ssh -f -N els-db"
```

**Почему 5434, а не 5432.** На ноутбуке 5432 занят постгресом из `make up`,
5435 — тестовым. Совпади порты — pgAdmin молча подключился бы к локальной
деве вместо боевой базы, и правка ушла бы не туда. Подробнее:
[[локальный конец туннеля к проду - 5434, а не 5432]].

Туннель намеренно **не** поднимается сам при загрузке Mac: пусть вход в
боевую базу останется осознанным шагом.

## Локальная разработка

```bash
make up      # весь стек в docker, веб на http://localhost:8080
make down    # погасить
make ps      # что запущено
make logs    # логи стека
```

Только бэкенд, без docker:

```bash
make sync    # поставить зависимости (uv)
make dev     # uvicorn с автоперезагрузкой на :8000
```

Локальная база после `make up`: `localhost:5432`, тестовая — `localhost:5435`.

## Перед коммитом

```bash
make lint    # ruff check + format --check
make format  # автоисправления
make test    # поднимет тестовую БД и прогонит pytest
```

Если менялся контракт API — пересобрать снимок и показать дифф в ревью:

```bash
make openapi-update
```

## Миграции

```bash
make migrate         # alembic upgrade head
make migrate-status  # какая ревизия сейчас в базе
```

На проде отдельный шаг не нужен: `prestart.sh` в контейнере бэкенда сам
делает `alembic upgrade head` до старта uvicorn.

## На сервере

Зайти: `ssh els`. Репозиторий — `/var/www/els`, команды оттуда.

```bash
make prod-deploy  # забрать образы этого коммита, накатить миграции, дождаться
make prod-ps      # что запущено
make prod-logs    # логи
make prod-down    # погасить (данные в volume остаются)
```

`prod-deploy` выкатывает тег `sha-<хеш HEAD>`, а не `latest`: сразу после
`git pull` образов ещё нет, CI собирает их 3–5 минут. Команда сама ждёт их
до 10 минут — раньше в это окно тихо уезжала прошлая сборка.

Откатиться на прошлую сборку:

```bash
IMAGE_TAG=sha-<полный хеш коммита> make prod-deploy
```

Правка конфига nginx (именно пересоздание, не `restart` — иначе контейнер
видит старый файл по inode):

```bash
make prod-nginx
```

Сертификат Let's Encrypt:

```bash
make cert-info        # что выпущено и до какого числа
make cert-renew       # продлить и перезагрузить nginx
make cert-renew-dry   # прогнать продление вхолостую
```

## Снять дамп прод-базы

Перед всем, что трогает данные. Кладётся в текущую папку на ноутбуке:

```bash
ssh els 'docker exec postgres pg_dump -U els_admin postgres' | gzip > els-$(date +%F).sql.gz
```

## База знаний

```bash
make vault-check  # имена файлов vault на Windows-совместимость
```

## Что и так поднимается само

Прод-стек переживает перезагрузку сервера без участия человека: служба
docker включена в systemd, у `postgres`, `backend` и `frontend` политика
`restart: unless-stopped`. Проверить:

```bash
ssh els 'systemctl is-enabled docker && docker ps'
```
