# План - запустить проект локально в docker

Цель: `make up` в корне поднимает всю систему, веб открывается в браузере,
телефон (iOS/Android) работает с тем же бэкендом. Одна кодовая база на три
платформы, без дублирования.

## Что в docker может быть, а что нет

| Часть | В docker | Как запускается |
|-------|----------|-----------------|
| PostgreSQL | да | контейнер |
| Бэкенд | да | контейнер |
| Веб-приложение | да | сборка Flutter web внутри образа + nginx |
| iOS / Android | **нет** | с хоста, `flutter run` на устройство/симулятор |

Мобильные сборки в контейнер не заворачиваются: Android нужен SDK и эмулятор
с доступом к ядру, iOS собирается только на macOS с Xcode. Docker даёт им
**бэкенд**, а не сборку. Приложение при этом одно и то же — разница лишь в
адресе API.

## Единая точка входа

nginx отдаёт и приложение, и API с одного origin:

```
localhost:8080/           → веб-сборка Flutter
localhost:8080/api/v1/    → проксируется на backend:8000
localhost:8080/docs       → Swagger бэкенда
```

Почему так, а не два порта: браузеру не нужен CORS (origin один), а фронту не
нужно знать адрес бэкенда — достаточно относительного `/api/v1`. Телефон ходит
на тот же nginx по IP машины в локальной сети.

## Шаги

### Шаг 1 — узнать, компилируется ли код (4–12 ч, главная неизвестность)
Сборка запускается в контейнере (`frontend/Dockerfile`, образ
`ghcr.io/cirruslabs/flutter:stable`), поэтому SDK на машине для этого не нужен.
Код писался под Dart 2.17, собираться будет под Dart 3 — часть ошибок
гарантирована, объём заранее неизвестен. Пока этот шаг не закрыт, остальные
оценки условны.

Для мобильных сборок и hot reload Flutter локально всё равно понадобится —
ставить через `fvm`, чтобы версия была зафиксирована в репозитории.

### Шаг 2 — адрес API в конфиг (2–4 ч)
Сейчас все 65 файлов собирают URL как `'http://${IntTest.myIp}/api/v1/...'`.
Заменить на единую константу, читаемую из окружения сборки:

```dart
class ApiConfig {
  static const String base =
      String.fromEnvironment('API_BASE_URL', defaultValue: '/api/v1');
}
```

- веб в docker: `/api/v1` (относительный путь, тот же origin);
- телефон: `--dart-define=API_BASE_URL=http://<IP машины>:8080/api/v1`;
- Android-эмулятор: вместо IP машины `10.0.2.2`.

Замена механическая (sed по 65 файлам), но делать её **отдельным коммитом**
и проверять пересборкой. Заодно убрать заглушку `reqres.in` с экрана сотрудников.

### Шаг 3 — починить платформенные импорты (8–16 ч)
Без этого мобильных сборок не существует: `import 'dart:html'` в двух файлах
и web-only `image_picker_web` в восьми ломают компиляцию под Android/iOS.
Кросс-платформенный `image_picker` уже в зависимостях, `kIsWeb` в коде
используется 28 раз — то есть заменяется штатно, экраны переписывать не надо.
Это и есть «не дублировать код»: один экран, внутри ветка по платформе.

### Шаг 4 — docker-стек (готово, проверяется шагом 1)
- `frontend/Dockerfile` — multi-stage: сборка web → nginx;
- `infra/nginx.conf` — проксирование `/api/v1/` на бэкенд, SPA-fallback;
- сервис `frontend` в `infra/docker-compose.yml`, порт `8080` наружу;
- бэкенд порт наружу больше не публикует — только через nginx.

### Шаг 5 — запуск на телефоне (2–4 ч)
```
flutter run -d <device> --dart-define=API_BASE_URL=http://192.168.1.X:8080/api/v1
```
Телефон и компьютер в одной сети. iOS-симулятор понимает `localhost`,
Android-эмулятор — `10.0.2.2`.

## Оценка

| Шаг | Часы |
|-----|------|
| 1. Поднять компиляцию под Dart 3 | 4–12 |
| 2. Адрес API в конфиг | 2–4 |
| 3. Платформенные импорты | 8–16 |
| 4. Docker-стек | сделано |
| 5. Запуск на телефоне | 2–4 |
| **Итого до «работает локально везде»** | **16–36 ч** |

Дедупликация ролевых экранов (100–150 ч) в эту цель не входит — она про
стоимость дальнейшей разработки, а не про запуск.
