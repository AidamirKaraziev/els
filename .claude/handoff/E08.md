### S01 — POST и PUT /type-acts/ (2026-09-18, влит в main отдельно)

- `POST /api/v1/type-acts/` `{name}` — id = max+1 (`crud_type_acts.create_next`),
  имя strip, пустое → 422, дубль → 409 (`ConflictEntity`, новый класс в
  `src/exceptions.py`). `PUT /type-acts/{id}/` — те же проверки, чужой id → 404,
  своё имя повторно → 200. Старый GET не тронут.
- Право `DIRECTORY_WRITE` теперь и у прораба (`src/core/permissions.py`) —
  вместе с видами ТО он получил запись во все справочники (города,
  специальности); матричные тесты ролей поправлены под это.
- Тесты: `tests/test_api_type_acts.py` (14), снимок OpenAPI +2 ручки.
  `make lint` зелёный, `make test` — 1096 passed.
- Руками на `make up` не проверялось — фронт ручку зовёт только в S05.

## Следующий этап

**Цель.** S02 «шаблоны: список по модели, steps как массив, канонический
step_list» · back.

**Готово, когда.** GET /acts-bases/ фильтрует по factory_model_id и отдаёт
имена и число шагов, GET /acts-bases/by-model/{id}/ помечает виды без шаблона,
POST/PUT принимают steps и пишут канонический JSON (step_list живёт
deprecated), parse_checklist читает результат, тесты зелёные. Плюс решение
про мягкое удаление `acts_bases` (ниже) учтено в контракте.

## Первые шаги

1. `backend/src/models/act_base.py` — `step_list = Column(String)`: узнать
   формат, который сегодня читает `parse_checklist`
   (`backend/src/services/checklist.py:267`) — канонический JSON должен
   проходить через него без правок парсера.
2. `backend/src/api/api_v1/endpoints/act_base.py` — текущие GET/POST/PUT;
   новую форму (`steps: list[str]`) добавлять рядом, `step_list` оставить
   принимаемым и пометить deprecated в описании.
3. Принято в S03 (2026-09-20): «вид у модели» на бэке = строка в
   `acts_bases` (шаблон, пусть с пустым `step_list`); удаление — **мягкое,
   колонка `acts_bases.deleted_at`**, не DELETE; «Вернуть» = обнулить
   `deleted_at`; мастер графика и предпросмотр удалённые пары не предлагают.
   Справочник `types_acts` не меняется. Одна Alembic-миграция на `deleted_at`.
   Почему мягко: акт при создании графика копирует шаги в
   `acts_fact.step_list_fact` (`backend/src/crud/crud_schedule_plan.py:137`),
   старые акты от правки шаблона не страдают; но DELETE `acts_bases` обнулил
   бы `acts_fact.act_base_id` (FK `SET NULL`) — ссылку терять нельзя.
4. `make openapi-update` после новых ручек/полей; тесты по образцу
   `tests/test_api_type_acts.py` (фикстуры `client_with_db`, `as_role`).
