# Передача: телефон умеет принимать push, но на устройстве это ещё никто не видел

## Сделано и проверено

- `frontend/lib/mechanic/data/push_service.dart` — единственное место с
  Firebase: `init()` из `main()` (Firebase, канал `emergency` importance max
  + звук + вибрация, запрос разрешения), `attach(onMessage:)` из
  `MechanicWorkspace.start()` (фореграунд → локальное уведомление +
  `refresh()`; тап по уведомлению → `refresh()`; `onTokenRefresh` → повторный
  `POST /device-token/`), `unregister()` из `signOut()` до `Api.logout()`.
  Не Android → все методы пустые; на вебе `Firebase.initializeApp()` не зовётся.
- В журнал (`notifications.dart`) push не пишет: `refresh()` вытянет
  изменения, и синхронизация сама положит «Новая задача»/«снята».
- `pubspec.yaml`: firebase_core 4.15, firebase_messaging 16.7,
  flutter_local_notifications 19.5; `pub get` прошёл, `intl` остался 0.20.3,
  `pubspec.lock` только вырос (+96 строк).
- Android: `com.google.gms.google-services` 4.4.2 (settings + app gradle),
  `coreLibraryDesugaringEnabled` + `desugar_jdk_libs:2.1.4`, в манифесте
  `POST_NOTIFICATIONS` и `default_notification_channel_id=emergency`.
- `dart analyze` по четырём тронутым файлам чист; `flutter test test/mechanic`
  — 139 зелёных; `flutter build apk --release` собрался локально (71,5 МБ,
  11 мин — Gradle качал Firebase); `flutter build web --release` собрался.
- Бэкенд не трогался: `make lint`/`make test` гонялись на старте при вливании
  S03 (1072 зелёных).

## Не доделано

- **Не проверено руками.** Push на устройстве никто не видел — ни в закрытое
  приложение, ни в открытое, ни снятие токена при выходе. Именно это и есть
  критерий этапа; всё остальное сделано.
- Код не закоммичен — коммит за пользователем (PyCharm, корень E10).

## Следующий этап

**Цель.** Тот же S04: увидеть push на телефоне со звуком и закрыть этап.

**Готово, когда.** Приложение закрыто → задача назначена с сайта → телефон
уведомил со звуком; открыто → то же через локальное уведомление; выход
снимает токен (`DELETE /device-token/` в логе бэка).

## Первые шаги

1. Поставить APK из прогона CI (или локальный
   `frontend/build/app/outputs/flutter-apk/app-release.apk` — он подписан
   debug-ключом, обновление поверх не встанет). Войти механиком.
2. Токен из `adb logcat | grep "push: токен"`. Дальше
   `cd backend && uv run python -m src.services.push --token <…>` — при
   закрытом и при открытом приложении. Нужен `backend/firebase-service-account.json`.
3. Назначить заявку с сайта на этого механика — проверить полный путь через
   `endpoints/order.py`. Выйти из приложения → в логе бэка `DELETE /device-token/`.
4. Если звука нет: канал `emergency` создался до первого push? Проверить в
   настройках приложения → Уведомления; канал с неверными свойствами удаляется
   только переустановкой.
5. Всё прошло → `/stage-end` со статусом `закрыт`.

## Не трогать

- Экран очереди отправки и фото на диск — S05.
- Код сайта; `endpoints/app_release.py` — раздача APK, это S07.
- Push по смене статуса — сознательно нет: телефон видит опросом.
- Переход к конкретной заявке по тапу на уведомление — не в этом этапе.
