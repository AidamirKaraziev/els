# Передача: сервер умеет слать push по заявкам, телефон их ещё не принимает

## Сделано и проверено

- Таблица `device_tokens` (миграция `a4c1e7b9d2f0`, up/down на тестовой базе
  прошли). `POST /device-token/` и `DELETE /device-token/` — любой вошедший,
  тело `{token, platform}`; повтор не плодит строк, чужой токен перевешивается.
- `src/services/push.py`: OAuth2 JWT bearer через `python-jose` + `httpx`, без
  новых зависимостей. Живой access_token от Google получен с ключом
  `backend/firebase-service-account.json` (`uv run python -m src.services.push`).
- Push уходит в `BackgroundTasks` из `endpoints/order.py`: создание → исполнитель
  и механик объекта; смена `executor_id` → новому «Новая задача №N», прежнему
  «передана другому»; архив → «снята». Смена статуса не шлёт. Автор себя не
  получает. Мёртвые токены (`UNREGISTERED`/`INVALID_ARGUMENT`) удаляются.
- Сообщение: `notification{title, body}` + `data{kind, order_id}` +
  `android{priority: high, channel_id: "emergency", sound: default}`.
- Ключа нет / `FIREBASE_SERVICE_ACCOUNT` пуст → push молча выключен, заявки
  работают. Compose dev и prod монтируют ключ read-only.
- `make lint` чист, `make test` — 1072 зелёных (14 новых `tests/test_push_orders.py`),
  снимок OpenAPI обновлён.
- На устройстве не проверено — телефон токен ещё не регистрирует (S04).

## Первые шаги

1. `frontend/android/build.gradle` + `app/build.gradle` — плагин
   `com.google.gms.google-services` (Groovy, `applicationId ru.els23.app`);
   `google-services.json` уже лежит в `frontend/android/app/`.
2. `pubspec.yaml`: `firebase_core`, `firebase_messaging`,
   `flutter_local_notifications`. Канал Android — `emergency`, importance max,
   звук + вибрация. `flutter pub get` придётся запустить — версии `intl`
   в CI и локально расходятся, проверить `frontend.yml` после.
3. `frontend/lib/mechanic/data/mechanic_workspace.dart:51` — после логина
   `getToken()` → `POST /device-token/`, `onTokenRefresh` → повтор; в
   `profile_screen.dart` при выходе `DELETE /device-token/`. Фореграунд:
   `FirebaseMessaging.onMessage` → локальное уведомление + `refresh()`.
   `data.kind` ∈ `order_assigned | order_reassigned | order_removed`.
4. Проверка живым push: `uv run python -m src.services.push --token <из логов
   телефона>` — шлёт тестовое сообщение, минуя сайт.
