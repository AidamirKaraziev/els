# Передача: APK 1.0.2 раздаётся с сайта, публикация — одной командой

## Сделано и проверено

- `https://els23.ru/app` под логином: «Версия 1.0.2 · 68 МБ», sha256
  `48af24db…c363e5` == лог CI прогона 35255069016. `POST /api/v1/app/link` →
  ссылка на минуту, `GET /app/download` → 200, `els-1.0.2.apk`, 71 647 942 байта.
- На Xiaomi обновление 1.0.1 → 1.0.2 через экран «Приложение» встало.
- `make apk-publish ARGS='--run <id> --notes "…"'` с ноутбука:
  `scripts/publish-apk.sh` — артефакт `els-apk` → версия из pubspec того
  коммита → sha против лога CI и отказ на debug-ключе → `docker cp` в
  `backend:/app/static/app/` (сначала APK, потом `release.json`).
- `docs/server-deploy.md` §3.4 «Выпуск APK»; §3.3 — «push без звука» →
  громкость уведомлений MIUI.
- `frontend/pubspec.yaml` `1.0.2+3`. Коммит `9cf1ad7` ушёл сразу в
  `origin/main` (не через ветку) — CI собрал APK с main.
- `make lint` чист, `make test` 1076 зелёных.

## Не доделано

- `GET /app/download` не отдаёт `Range` (200 вместо 206): докачка после
  обрыва невозможна. На установку не влияет; если механики жалуются на
  обрывы — смотреть `X-Accel-Redirect` в `infra/nginx/app.conf`.
- В томе `static/app/` лежат старые `els-1.0.0.apk`, `els-1.0.1.apk` — бэк
  их не читает, 140 МБ можно удалить руками (`docker exec … rm`).
- `version.json` из формулировки плана = `release.json` бэка; отдельного
  файла нет и не будет.
