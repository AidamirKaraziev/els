# Передача: форма подключена к живым ручкам, осталось выкатить и посмотреть на проде

## Сделано и проверено

- `GET /work/new/context` (`endpoints/work_feed.py`) — объекты области с
  механиком/прорабом/контактом, категории с кодом и именем без префикса,
  сотрудники ленты плюс заказчики (`specialty="Заказчик"`), открытые работы
  по объекту, `my_sections`, `author`. Право `order:create`.
- `POST /order/` принимает `executor_id: null` (и `0` → никто); исполнитель
  проверяется по-настоящему (`crud_order.py:95`, раньше `.first()` не было).
- Миграция `e9b7d4a06c32` сеет категории Р, НЛ, ЗЧ, О, ПР, М, УБ, ДОК, ДР
  (`counts_as_breakdown=false`, id ≥ 11, идемпотентно по имени); те же в
  `init_db.check_fault_category`, отбор там теперь по имени.
- Фронт: `WorksScreen(canCreateWork: true)` у админа (`home_page.dart`) и
  прораба (`home_foreman.dart`); справочники и создание — через
  `WorksRepository.newWorkContext()/createWork()`; после успеха
  `WorksRequested()` + «Работа №N создана»; ошибка бэка — его `description`
  строкой в форме. ТО и Л скрыты по коду в `NewWorkContext.fromJson`.
- `make lint` чист, `make test` — 1058 зелёных (`tests/test_api_new_work.py`
  — 9 новых), снимок OpenAPI обновлён. `flutter test test/works` — 38
  зелёных, `dart analyze` чист. В превью на фикстуре (`works-preview`)
  работа создаётся, счётчики ленты обновляются.
- **Не проверено руками на живом стеке** — это S03.

## Не доделано

- Фото в форме: `_pickPhoto` ставит только имя файла. Выбор файла и
  `POST /order-photo/{order_id}/` — отдельный этап, по решению пользователя.
- Первый клик по строке списка объектов после набора текста под автоматикой
  браузера уходит в поле поиска (воспроизвелось в превью и без набора текста);
  руками не проверено. Если мешает — `_ObjectSearch` в `new_work_dialog.dart`.
