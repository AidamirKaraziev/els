# Выкат на сервер

Инструкция для сервера с 1 ядром, 1 ГБ памяти и 15 ГБ диска.

## Как это устроено

Сервер **не собирает** образы. Их собирает GitHub Actions и кладёт в
`ghcr.io`, а сервер только скачивает готовое и запускает.

Так сделано не из любви к красоте: `flutter build web --release` требует
несколько гигабайт оперативки и образ Flutter SDK на 3.76 ГБ. На 1 ГБ сборка
падает по OOM в середине и оставляет мусор в кэше.

Миграции накатывает сам контейнер бэкенда: `prestart.sh` делает
`alembic upgrade head` до старта uvicorn. Отдельной команды для них нет.

---

## Часть 1. Один раз в GitHub

### 1.1 Дождаться первой сборки

Запушьте `main` — это запускает `.github/workflows/release.yml`. Во вкладке
**Actions** должна пройти джоба `release` с двумя сборками: `backend` и
`frontend`. Фронт собирается несколько минут.

### 1.2 Открыть доступ к образам

Пакеты в `ghcr.io` создаются приватными даже у публичного репозитория. Если
этого не сделать, сервер получит `denied` при скачивании.

На странице репозитория → **Packages** → по очереди `els-backend` и
`els-frontend` → **Package settings** → **Change visibility** → **Public**.

Альтернатива, если образы должны остаться закрытыми: создайте токен с правом
`read:packages` и один раз выполните на сервере
`docker login ghcr.io -u <логин>`.

## Часть 2. Один раз на сервере

### 2.1 Docker

```bash
curl -fsSL https://get.docker.com | sh
```

```bash
sudo usermod -aG docker $USER
```

После второй команды нужно перезайти по SSH, иначе docker будет требовать
`sudo`.

### 2.2 Swap

На 1 ГБ памяти это не роскошь, а страховка: генерация PDF с фотографиями
держит картинки в памяти, и без swap совпадение двух таких запросов уронит
контейнер.

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
```

Чтобы swap пережил перезагрузку:

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 2.3 Репозиторий

Нужен не ради кода, а ради `infra/docker-compose.prod.yml` и
`infra/nginx.conf` — они монтируются с диска. Без образов это несколько
мегабайт.

```bash
git clone https://github.com/AidamirKaraziev/els.git && cd els
```

```bash
sudo apt install -y make
```

### 2.4 Файл `.env`

Создайте `.env` в корне репозитория. Обязательный минимум:

```
MODE=PROD
DB_USER=els
DB_PASS=<длинный пароль>
DB_NAME=els
DB_HOST=postgres
DB_PORT=5432
SECRET_KEY=<длинная случайная строка>
WEB_PORT=80
BACKEND_CORS_ORIGINS=https://ваш-домен
```

Четыре вещи, которые легко пропустить:

**`MODE` — любое значение, кроме `TEST`.** В коде оно влияет ровно на одно:
при `MODE=TEST` приложение **не создаёт** начальные данные (`main.py:58`).
Поставите `TEST` на сервере — на чистой базе не появятся ни роли, ни статусы,
ни категории неисправностей, ни суперадмин, и войти будет некем. `PROD`
выбран потому, что по нему сразу видно, куда смотришь.

**`SECRET_KEY` задавать обязательно.** Если его нет, приложение генерирует
случайный при каждом старте — и все выданные JWT становятся недействительны.
Люди будут разлогиниваться при каждом выкате. Сгенерировать:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

**`DB_HOST=postgres` в `.env` не важен для контейнера** — compose всё равно
перебивает его на `postgres`. Но оставьте, чтобы не спотыкаться при запуске
бэкенда с хоста.

**`BACKEND_CORS_ORIGINS`** сейчас пуст, и API открыт для любого домена — в
логе на старте висит предупреждение. Впишите свой домен.

Пример со всеми переменными: `backend/envs/.env.prod`.

## Часть 3. Каждый релиз

### 3.1 Локально: запушить

```bash
git push origin main
```

Дождитесь зелёной джобы `release` в Actions. Пока она не прошла, на сервере
делать нечего — там лежат прошлые образы.

### 3.2 На сервере: обновить конфиги и выкатить

```bash
cd els && git pull
```

```bash
make prod-deploy
```

Команда скачивает образы, поднимает стек, ждёт, пока бэкенд станет здоровым
(это и означает, что миграции прошли), и печатает накатанную ревизию Alembic.

Если `make` не установлен, то же самое напрямую:

```bash
docker compose --project-directory . -f infra/docker-compose.prod.yml pull && docker compose --project-directory . -f infra/docker-compose.prod.yml up -d --wait
```

### 3.3 Проверить

```bash
make prod-ps
```

У `backend` должен быть статус `healthy`. Открыть сайт по адресу сервера.

## Часть 4. Домен

Домен проекта — **els23.ru**, регистратор Timeweb, там же управляется DNS.

### 4.1 DNS

Записи `A` для `els23.ru` и `www.els23.ru` должны указывать на IP сервера.
Проверить:

```bash
dig +short els23.ru A
```

Обе записи уже переключены на `213.171.3.254`.

### 4.2 Отдать сайт на 80-м порту

В `.env` на сервере:

```
WEB_PORT=80
```

Без этого домен пришлось бы открывать как `els23.ru:8080`, а Let's Encrypt
не смог бы проверить владение доменом — он стучится строго на 80-й порт.

Порт 443 публикуется автоматически, ещё до получения сертификата. Пока nginx
внутри контейнера его не слушает, он просто закрыт — вреда нет, зато
включение HTTPS не потребует пересоздавать контейнер.

Применить:

```bash
make prod-deploy
```

### 4.3 Проверить

```bash
curl -I http://els23.ru
```

Ожидаем `200`. Если ответа нет вовсе — порт закрыт фаерволом сервера или
провайдера, это надо чинить до сертификата.

Заодно убедиться, что ссылки на файлы собрались с доменом, а не с IP:

```bash
curl -s http://els23.ru/api/v1/divisions/ | head -c 300
```

Бэкенд строит их из заголовка `Host`, поэтому отдельной настройки не нужно.

## Если что-то пошло не так

`make prod-deploy` при неудаче сам печатает последние 60 строк лога бэкенда —
чаще всего причина там.

Логи целиком:

```bash
make prod-logs
```

Откат на предыдущую сборку. Каждый образ тегируется полным хешем коммита,
пересобирать ничего не нужно:

```bash
IMAGE_TAG=sha-<полный хеш коммита> make prod-deploy
```

Хеш берётся из истории: `git log --oneline`, только тег содержит полный
40-символьный хеш, а не короткий.

Погасить стек (данные в томах остаются):

```bash
make prod-down
```

## О чём помнить

**Диск съедят фотографии.** Том `static_data` хранит фото заявок и актов и
сгенерированные PDF. Растёт линейно и сам не чистится. Три фото по 4 МБ на
акт, сто актов в месяц — полтора гигабайта в месяц, и через год 15 ГБ
кончатся. Смотреть так:

```bash
docker system df -v
```

**HTTPS нужен не для красоты.** Без него браузер не отдаёт геолокацию и не
регистрирует service worker: карта с позицией на телефоне не работает вовсе,
приложение не ставится на домашний экран. Понадобится домен и обратный прокси
с сертификатом перед контейнером фронта.

**PostgreSQL наружу не смотрит** — порт привязан к `127.0.0.1`. Чтобы
подключиться клиентом с ноутбука, поднимите туннель:

```bash
ssh -L 5432:localhost:5432 user@server
```

**pgAdmin в стеке нет.** Он съедал 173 МБ памяти — шестую часть всей машины.

**Первый выкат заведёт суперадмина** с логином `1` и паролем `1`
(`create_super_admin` в `backend/src/core/db/init_db.py`). Смените пароль
сразу после первого входа.
