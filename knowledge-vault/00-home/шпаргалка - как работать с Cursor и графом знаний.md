# Шпаргалка - как работать с Cursor и графом знаний

Цель: чтобы Cursor/Claude **быстро поднимал контекст** из `knowledge-vault/` и **оставлял след** (решения, баги, паттерны, логи сессий).

## Ежедневный workflow (минимум действий)

### Старт
1. Открой `knowledge-vault/00-home/index.md`
2. Открой `knowledge-vault/00-home/текущие приоритеты.md`
3. В Cursor сформулируй задачу одной фразой: “что делаем” + “зачем”.

### Во время работы
- Если трогаешь новый модуль/сущность — попроси Claude сначала прочитать релевантные заметки из `atlas/` и `knowledge/`.
- Если появилось важное “почему” (ограничение/компромисс/правило) — фиксируй это в vault сразу, не в конце.

### Финиш
- Напиши в Cursor: **«сохрани сессию»** — Claude должен:
  - создать лог в `knowledge-vault/sessions/`
  - обновить `текущие приоритеты.md`
  - добавить решения/баги/паттерны при необходимости
  - обновить `index.md`, если появились новые ключевые заметки

## Готовые команды (копируй в Cursor)

### Перед началом задачи
**Команда**:
Прочитай `knowledge-vault/00-home/index.md` и `knowledge-vault/00-home/текущие приоритеты.md`.  
Если задача про БД/модели/миграции — прочитай `knowledge-vault/atlas/база данных - PostgreSQL + SQLAlchemy 1.4 + SessionLocal.md` и `knowledge-vault/knowledge/patterns/миграции Alembic - версии в alembic versions и импорт моделей из src.models.md`.  
Потом предложи план и начни.

### Проверить, что vault переносим на Windows
**Команда**:
Запусти `make vault-check`. Если есть ошибки — переименуй заметки так, чтобы не было символов `< > : " / \ | ? *` и чтобы имя не заканчивалось пробелом/точкой.

### Зафиксировать архитектурное решение
**Команда**:
Зафиксируй решение в `knowledge-vault/knowledge/decisions/` отдельной заметкой (1 заметка = 1 решение), в названии — утверждение.  
Добавь 2–5 wiki-ссылок `[[...]]` на связанные заметки и обнови `knowledge-vault/00-home/index.md`, если решение ключевое.

### Зафиксировать баг и фикс
**Команда**:
Создай заметку в `knowledge-vault/knowledge/debugging/` и запиши: симптом → причина → фикс → как проверили.  
Свяжи с затронутыми сущностями через `[[...]]`.

### Зафиксировать паттерн (“как принято делать”)
**Команда**:
Опиши паттерн в `knowledge-vault/knowledge/patterns/` (коротко: когда применять, когда не применять, пример).  
Свяжи с `[[архитектура проекта - FastAPI API + CRUD + getters + SQLAlchemy модели]]`.

### Добавить “сырые” заметки
**Команда**:
Сложи всё неоформленное в `knowledge-vault/inbox/` (одна тема = один файл), потом разнесём по `knowledge/`.

## Как пользоваться Obsidian
- **Wiki-ссылки**: пиши `[[название заметки]]` в тексте — Obsidian создаст связь.
- **Graph View**: смотри на “одинокие” заметки без связей — это точки, где не хватает контекста.
- **Правило названий**: название файла = утверждение, чтобы Claude понимал релевантность ещё до открытия.
